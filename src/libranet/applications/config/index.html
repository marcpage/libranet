What this node says of itself

Pages show this node by its name, on this node and on others, with the rest of what it says when the name is hovered over or tapped. It is public: the node signs each version and keeps it in the network, where anyone can read it. Every detail is optional, and you may add any other.

Other nodes

This node learns of other nodes from those it connects to, so reaching one node of a network is enough to join it. Give the address of a node to reach, and this node connects to it now, and says whether it could. A node it reaches is known from then on, as every node it reaches is, and is listed in the nodes application.

Connect to a node

An address is the host name or IP address of the node's machine, and the port the node listens on. Reaching a node that does not answer can take a minute.

Trust

This node keeps a list of the nodes it trusts, and those it distrusts. A person who trusts this node reaches through its list: their trust scores count the nodes it trusts, and against those it distrusts, a tenth as strongly as their own. The list is public: the node signs each version and keeps it in the network, where anyone can read it.

Node Trust Actions

Trust or distrust a node

A node's id is on its page in the nodes application, and under "This node" on its own administration page.

Applications

Each serves a directory bundle as a website at /{name}/. The root application, named /, also answers every path no other one claims.

An application you have not trusted is served in a sandbox: its pages can show what the network holds, and nothing more. A trusted one can import any file from the folders this node offers, make bundles, and read and change every application's store, so trust only one you would trust with those folders.

Served at Bundle Trusted Actions

Register an application

A name already registered, however it is cased, serves the new bundle instead. An application is not trusted once it is registered, or given another bundle, until you trust it in the list above.

Users

A person signs in to this node's applications with a username and password. Their identity is kept in the network, encrypted by both, so they can sign in with them on any node that holds it. This node keeps no list of the people who have one, and a forgotten password cannot be reset. Each person also has a fallback password, which signs in as a second identity made with the first, their fallback, should the first be compromised. Once you create one, you are offered a link that adds them to the user directory.

Create a user

A username is the same however it is cased, and a password is at least 8 characters. The fallback password is another, which the person keeps apart from the first, written down, say, since whoever learns both can take over the identity for good. A larger key takes longer to make, and to guess. Creating a user takes about ten seconds, and does not sign you in.

Builds

Each makes a directory on this machine into a bundle, and records the bundle's content id beside the directory, in {name}.bundle. Building it again makes a new version, which names the one before. A bundle is served only once it is registered as an application. Builds are forgotten when the node restarts, but the record beside each directory is kept.

Build a directory

Leave the password empty to build a bundle that can be served as an application; a password-protected one cannot be served yet. Anyone who learns a protected bundle's content id can try passwords against it without limit, so use a long, random one.

Exports

Each writes a bundle, and everything needed to serve it, into a content archive. A node started with the archive among its storage.archives holds the bundle, and serves it once it is registered there. Exports are forgotten when the node restarts.
